# Stage 9 — Retarget everything to the published `opencode2` binary

## Why

`@opencode-ai/cli@0.0.0-beta-18286` (binary `opencode2`) is published and is the **exact** build of our pinned `@opencode-ai/client@0.0.0-beta-18286`. Every earlier "no published server exists" conclusion came from probing `opencode-ai` — the **legacy v1 package name**. Verified live (2026-08-27, orchestrator): `health.get()` → `{healthy:true, version:"0.0.0-beta-18286"}`, `migration.v1.status()` → `completed`, `session.create` OK, `session.instructions.entry.put/list` OK (round-tripped `[{"key":"probe","value":"hello"}]`). Basic auth username is **`opencode`**, password printed by `serve` as `server password <...>`; `/api/doc` does **not** exist on this build (404 when authenticated).

**The provider source needs no rework** — `src/` never referenced the CLI or source build; it was written contract-first against the pinned client types, which is precisely what `opencode2` serves. This stage swaps the *harness* and corrects *claims*.
